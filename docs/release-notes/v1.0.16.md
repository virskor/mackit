## Mackit 1.0.16

The monitoring surfaces now show the CPU's real temperature, the scans behind every page got faster, and apps you removed leave less behind.

- **The temperature is shown in degrees** — read through the SMC and shown in whole degrees on the menu bar, in the panel and on the desktop stats, orange from 70°C up, with the thermal-state word as the fallback when no sensor answers.
- **Scans finish sooner** — the project-junk walk, Downloads scan, app-residue probe and Application Support index read each directory in one bulk call instead of stat'ing every entry, the shared `~/Library` listings and language subtags are resolved once per scan, and the merge dedup index is maintained incrementally instead of rebuilt per batch.
- **The result pages render lighter** — the general cleanup page's hundreds of sub-rows render lazily, large-file rows cache their size text, and the treemap skips its re-sort when children already arrive largest-first.
- **Leftover caches of removed apps surface** — an app dragged to the Trash leaves its cache directories behind, and the scan now lists the unclaimed ones as an opt-in row with everything your installed apps and the other rules already own subtracted, so no byte is offered twice.
- **Xcode's device logs are cleanable** — the logs collected from connected devices are re-collected on the next connect, listed at the same review level as the device-support files.
- **Spotify's cache is no longer swept wholesale** — it holds your offline library rather than regenerable bytes, so it stays out of the app-junk sweep while the uninstall tool still removes it together with the app.
- **Ignore what you want to keep** — right-click any scan result to never see that path or that rule again; both lists live in a new settings tab, survive restarts and reach the tray agent, so an ignored rule costs nothing on the next scan.
- **Long lists fold** — the unused-language and app-junk rows start collapsed when they carry more than six entries and expand from the arrow in the row header, keeping their total and selection while folded, so a checked row still sweeps everything it holds.
- **Manage what opens at login** — the new 启动项 page lists every launch agent, launch daemon and legacy login item grouped by app, with a switch per entry and a master switch per app, and system-level services ask for your password once to install the Mackit helper service, whose whole job is flipping launchd's enabled state.

### Under the hood

- The SMC read opens one connection per sample and closes it on the way out, and its selection, filtering and decoding are a pure function over an injected key reader, so the logic is unit-tested without an SMC.
- The kext record's offsets are named constants, because a struct-derived `data8` lands in the record's padding, where the kext reads a zero command and every call fails.
- The merge's dedup index answers "is any already-listed entry inside this path?" by inverting it: the strict ancestors of every listed path are collected as items are appended, and the query is one set lookup.
- The leftover scan uses a pool design — enumerate `~/Library/Caches` and the sandbox containers' cache trees once, then subtract the claims of every static rule's literal target prefix and every installed app's bundle id, app name and bundle-id last segment — and it errs toward claiming, because a live app's cache offered for deletion is a bug while a missed leftover is only a missed cleanup.
- Deletion re-checks each entry's vnode identity (device, inode) after the re-measure walk, closing the swap window the path-only protected check leaves open.
- Ignoring is enforced at the two funnels: the rule tables the engine builds its work units from, so an ignored rule costs nothing to run, and the single merge funnel every scanner reports through, so one check covers the static rules, the app junk and leftover scans, the language and Downloads scanners and the project walk alike — while the leftover scanner's claim set still reads the whole catalog, because ignoring a rule must not turn the paths it used to own into leftover candidates.
- A grouped row's fold lives on the view model keyed by row id and invalidates the general page's cache through its own revision dimension, so a rescan rebuilds the rows without unfolding what the user folded, while a fold leaves the item and selection caches warm — and folding never moves the selection, so a collapsed checked row still sweeps everything it holds.
- The startup-items scan reads launchd's override database (`print-disabled`) rather than which services happen to be running, so a loaded-but-disabled service correctly reads as disabled — the state that decides the next login — and the Mackit helper service is a separate executable whose command set is five fixed `launchctl` argv vectors over validated labels, with no shell and no arbitrary command, that removes only its own two files when uninstalled — through the daemon when it answers and through an elevated one-shot run when it does not, so a broken install can always be repaired or removed.
