## Mackit 1.0.4

A maintenance release that fixes the two rough edges left in in-app auto-updating.

- **The menu bar updates with the app**: the tray agent runs as its own process inside the app bundle, and an auto-update only restarted the main app — so after updating, the menu bar kept showing the previous version's panel until you rebooted or logged in again. The app now restarts the agent as part of the first launch of the new version, and the tray is on the new code immediately.
- **Updates are noticed without checking by hand**: the update check used to run at most once a day, so opening the app within that window said nothing about a newly published version and you had to use "Check for Updates…" yourself. Every launch now checks, and when a new version is found the standard update window offers it — install now, skip this version, or remind you later.
- **Hands-off updating is still one switch away**: Settings › Updates now defaults to asking before downloading. Turn on "Automatically download and install updates" there if you prefer updates to arrive silently and install themselves when you quit.

### Under the hood

- The main app records its bundle version in its preferences at every launch; a mismatch against the running bundle means the resident tray agent predates it (Sparkle update, reinstall over an older copy, or downgrade), and the agent is terminated and relaunched from the fresh bundle. The relaunch runs in a detached shell so it survives the main app quitting, waits for the old agent to exit before opening the new one (a second instance refuses to start while another is alive), and force-kills whatever is left after a grace period.
- The launch-time update check is a background check issued right after Sparkle's updater starts — Sparkle's documented way to additionally check on every launch — gated on the automatic-checks setting so opting out is respected.
- The auto-download default flips to off: since Sparkle 2.4 that mode downloads silently and installs on quit without ever prompting, which is what made a new version invisible in the first place. The mode itself stays available as an opt-in.
- The About page's version row and the update controller's bundle-version marker now share one formatter (`Utilities/AppVersion.swift`) so the two can never drift apart.
- Unit tests cover the staleness rule (including downgrades) and the launch-to-launch marker round trip.
