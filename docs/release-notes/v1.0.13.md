## Mackit 1.0.13

"Show in Finder" now really shows the item, and the READMEs link straight to the download page.

- **"Show in Finder" reveals the item you clicked.** Everywhere else on the Mac the command brings a Finder window forward with the file or folder selected. Mackit's reveal probed the Finder automation permission first and never asked, so on a machine whose answer was not already "granted" — never asked, or Finder closed, which the probe reports the same way — every reveal opened the enclosing folder with nothing selected, a click that reads as a no-op. The reveal now asks for consent the first time it needs it, with the dialog any other app's first reveal shows: allow it and Finder comes forward with the item selected, refuse it and the enclosing folder still opens. The system records the answer, so the ask happens at most once and a refusal goes straight to the fallback instead of asking again on every click.
- **A folder is revealed selected, not opened into, and an app bundle is never launched.** "Show in Finder" on a folder now selects it in its enclosing window, exactly as a file is revealed — what the label always promised — and an application bundle is selected rather than opened, so revealing Xcode.app can never launch Xcode. The junk list, the disk analysis page, the large-file page, the crash log viewer and the uninstall page all reveal through the same code.
- **The READMEs link to the download page.** Each of the five READMEs carries a download link to mingcui.cn in its own language — the root path for Simplified Chinese, `/en`, `/zh-Hant`, `/ko` and `/ja` for the others — beside the existing GitHub Releases link.

### Under the hood

- Selecting is an AppleEvent to Finder, and an app not permitted to automate Finder gets silence rather than an error, which is why the click used to read as a no-op. The reveal now asks at the moment it first needs consent instead of gating on a probe that can never prompt, running the ask off the reveal's call stack because it blocks for as long as its dialog is up. The permission-free fallback — open the enclosing folder — is what a recorded refusal gets, and the selecting path still never hands a path to `NSWorkspace.open` itself, because LaunchServices opens a bundle with whatever app claims that kind of resource.
- `RevealInFinder.decision(for:)` maps the probe's answers onto the reveal: granted selects, never-asked requests once, refused opens without selecting, and a target that is not running still sends — with consent on record the event launches Finder and selects. Five unit tests pin each direction, 673 test functions in all (+3 since 1.0.12).
