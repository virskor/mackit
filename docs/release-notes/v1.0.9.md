## Mackit 1.0.9

Homebrew gets a manager — browse it, search it, install into it, upgrade it and clean it without leaving the app.

- **A Homebrew manager joins the Tools section.** Six sections: Installed, Upgrades, Install, Services, Diagnostics and Configuration. Selecting a package opens the facts a terminal user would look up — description, installed and latest versions, install date, whether it was requested or pulled in as a dependency, license, tap, size, homepage, and the dependency and dependent lists (a dependent is what blocks an uninstall, so it is named right where the uninstall button is). The lists filter by kind — formula / cask — and by origin: everything, only what you asked for, or only what came in as a dependency (the set `brew autoremove` would take), each option labelled with the row count it leaves. Services shows every service's status and PID with start / stop / restart, Diagnostics runs `brew doctor`, Configuration reads `brew config`. Mackit's own angle stays in the header: formulae and cask counts, the cache total, the Cellar total, and cleanup / autoremove / upgrade actions beside the exact terminal commands they run. No Homebrew on the machine? The page shows the official installer to copy and a recheck button that flips it into the manager once Terminal is done.
- **Install packages without a terminal.** The Install section searches brew's local index over formulae and casks, shows each hit's kind tag and description, and installs on the same path as every other action — progress pill, output log, and the lists refreshed the moment the package lands.
- **Every action shows its work.** Brew's output streams line by line into a pill pinned at the page's bottom corner: the plan, the current package, the elapsed time. Click it for the full log, which stays reachable for a few seconds after the action ends. The progress bar never invents a number — it counts brew's real per-package steps and stays indeterminate where brew states no total, as `brew cleanup` does.
- **The toast got a countdown; the copies got a receipt.** The toast wears a neutral plate with a small tinted icon chip and a hairline that drains across its seconds on screen, so the auto-dismiss no longer reads as the toast vanishing mid-sentence. And every copy button — the brew command rows, the diagnostics and configuration copies, the junk list's Copy Path — confirms itself with a toast; a copy that succeeded silently was indistinguishable from a dead button.
- **The cleanup rules grew.** The catalog now carries ninety rules: the Chromium family — Chromium, Brave, Arc, Opera and QQ Browser — each gets its Code Cache paired with its cache into one row of the general cleanup layout, and the Android SDK and Gradle JDK caches, Xcode's SwiftPM cache, the npx cache and the `simctl delete unavailable` command join the list. Simulator device data is no longer skipped wholesale, so the simulator device cache rules finally have something to clean.
- **A relocated toolchain is still cleaned.** Rule paths may name a toolchain location — `GOPATH`, `GRADLE_USER_HOME`, `PIP_CACHE_DIR` and fourteen more — resolved from the environment with the tool's documented default as the fallback, so a moved Go module cache or Gradle home is cleaned where it actually lives; with no variable set, behavior is exactly as before.
- **Toolchain categories wear their official marks.** Xcode, Android, Go, Node, Flutter, Rust, Python, CocoaPods and Homebrew draw as their official logos, vendored as SVGs and rendered in-app; a category without a mark keeps its SF Symbol.
- **Hardware detection sits with the other tools** in the sidebar's Tools section, beside disk analysis and Homebrew, instead of at the foot of the list. It is a read-only report about the machine — a utility, not a setting.
- **Fixed:** the About page and the share message open the official site at its new root address. The Homebrew manager reads a package brew reports without a version as unknown rather than printing Homebrew's own name as the version, keeps dependency-origin packages in the list when brew's on-request flag is unavailable instead of emptying it, and a cancel raised mid-action no longer dismisses the progress pill that was staying on screen.

### Under the hood

- **No output format is guessed.** Every brew command and JSON shape the manager parses was verified against a real Homebrew 7.x installation; the services JSON was read from brew's own source. Where brew's JSON cannot be read — an old brew without `json=v2` — the page degrades to the name+version list instead of blanking out, and disables only the two filters that need the missing flag.
- **The action pill's lifecycle belongs to the model, not the view.** A view that derives the pill from the running action's change notification loses any action that finishes between two render passes — SwiftUI coalesces the change away, and the pill never appears. The model raises the pill on the turn the action starts, keeps it up through a dwell after the finish, and pins it while the log popover is open.
- **Brew's output is pumped, not buffered.** Both pipes stream through a `SendablePipe` reader whose line splitting — a chunk boundary can fall mid-line — lives in a `LineBuffer` pinned by tests, so the progress count and the log see whole lines no matter where the reads break.
- **511 tests across 55 suites** cover the manager's parsers, the filters and their degraded-mode behavior, the pill lifecycle, the toast countdown, the environment-path resolution and the SVG path parser, and the localization keys in all three languages; the three hand-built in-card search fields consolidated into one `SearchField` component riding the same glass surface as every other control in the app.
