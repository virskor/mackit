## Mackit 1.0.7

The app's own surfaces, rebuilt for macOS 26 — and the toolbar and sidebar finally read as one piece each.

- **Liquid Glass on macOS 26 and later**: the action toast, the clean-progress card, the treemap's hover label, the tray panel's quit hint and clean pill, the disk-analysis navigation chevrons and every brand call-to-action now render in the system's Liquid Glass instead of the hand-painted plates they were. One component decides between the glass and the exact fill, hairline and shadow each surface painted before, so macOS 14 and 15 keep the appearance they had — the pilot that the brand buttons carried as an opt-in is now the default everywhere they appear, the results page's "Done" included. Glass replaces the fallback's hairline and shadow rather than stacking on them, and a disabled control stays on the flat fill, where a dimmed glass reads as broken rather than as "not now". The system's own controls — push buttons, switches, segmented pickers, the sidebar, tables, forms, progress views — follow the system's macOS 26 appearance and are deliberately untouched.
- **The content toolbar's actions carry real weight**: scan, sort, the safe-only switch, the search field and the clean button all ran on default metrics, so a button in the hand-built row rendered at text-button weight beside the prominent clean button and the whole strip read as scaffolding. The actions now use explicit bordered styles at the large size — the same treatment the results page already gave its rescan button — the switch steps up a size, the search field and the clean button grow to match, and the row gains height. Those styles are also what let the actions pick up the system's own macOS 26 surface, so the row reads as one piece on every OS rather than a styled button among naked ones.
- **The sidebar reads as one list**: every row is a single line at one height — the cleanup rows used to stack the item count under the title while the module entries were single-line, so a tall row and a short one alternated with no rule saying why — with the count folded in beside the size in a trailing slot every row has, filled or not, so the titles share one ragged edge. The figures hold their width when the sidebar narrows and the title gives way instead. The safe-only filter takes the same shape — icon, title, and its checkbox in the trailing slot where the figures sit — rather than hanging at the leading edge. The row-leading icons are larger, and the selected row is a light pill inset from the row's edges that darkens against the light sidebar and lightens against the dark one, with the row's own colors left alone; the 15% accent tint it replaces read as a hover state.
- **The toolbar's sort menu names the sort in force** instead of a fixed "Sort": after picking "earliest modified" the row still read "Sort" and the only trace of the choice was the checkmark inside the menu — the one place you weren't looking. The menu's label now shows the live sort, whether it was set from the menu or by clicking a column header.

### Under the hood

- **One component owns the glass switch.** `GlassSurface` gates `glassEffect` on macOS 26+ and paints the pre-26 plate below it, so the availability check and the old appearance are written once instead of `#available` repeated at every call site. What differs between the toast, the clean-progress card, the treemap's hover label and the brand CTA is only the glass variant, the outline and what sits on top — the mapping lives in a standalone `GlassStyle` so it is unit-testable without the generic parameter the surface itself needs. No `GlassEffectContainer` wraps these: a container merges glass layers that overlap or abut, and every glass surface in this app is a lone floating element.
- **The toolbar names a comparator, not a preset.** `sortComparator` is written by the table's header clicks as well as by the menu, so the live state is a comparator rather than one of the menu's presets; `ItemSort` gained the reverse lookup — every comparator a header click can produce (three fields × two directions) is one of the six presets, and the initializer stays failable so a future field has to be given a preset rather than silently reporting the wrong sort's name.
- **The sidebar's four module-entry rows were four copies of one layout**; they are now calls to the single row builder, with the figures in a trailing slot every row has.
- **365 tests across 42 suites** pin the new behavior: the glass style mapping — that a tinted style really resolves to tinted regular glass and that the interactive flag reaches the `Glass` value — and the comparator-to-preset round trip, where every preset must survive a trip through its comparator and every field × direction a header click can produce must resolve to a preset, so the row can never name a sort that isn't the one in force.
