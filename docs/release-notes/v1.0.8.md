## Mackit 1.0.8

The window finally wears the system's own macOS 26 clothes — starting with the traffic lights.

- **The traffic lights match the system default again.** The close, minimize and zoom buttons in the top-left corner rendered at the smaller pre-macOS-26 size — 12pt discs with their symbols always visible — while every other current app on the system, System Settings included, drew the macOS 26+ chrome: 14pt discs, 23pt spacing, symbols only while you hover, the softer glass shading. The cause was not the window's design but the build: the app declared itself as built against the macOS 14 SDK, and macOS keys a whole generation of window chrome off that declaration. The window keeps its hidden title bar and full-bleed layout — nothing about the app's own layout changes, only which chrome the system draws on it.
- **System-styled controls take the macOS 26+ metrics with it.** The same declaration also governed control sizing: push buttons, switches, pickers, tables and forms now render at the current sizes — taller, rounder — instead of the pre-macOS-26 ones. This is the appearance the app was already written to pick up on macOS 26 and later; it just never got the chance to.
- **macOS 14 and 15 are unaffected.** The deployment target is unchanged, so the app still installs and runs on macOS 14 and later, and those systems — which have no macOS 26 chrome of their own — keep the appearance they always had.
- **The sidebar wears the system's Liquid Glass.** The left column rendered as a flat gray sheet while the system's own sidebars carry the translucent glass with its top-down specular gradient. The app was painting an opaque window background behind the entire split view — sidebar column included — so the sidebar's glass had a flat wall to sample instead of the window's glass backdrop; the storage block at the foot of the column wore a second, lighter slab of bar material, reading as a separate panel under the list. Both are gone on macOS 26 and later. The window backdrop stays clear so the glass samples the window directly, and the footer's slab gives way to a far lighter frost: the storage block is a bottom inset the list scrolls behind, so with no backdrop at all the last row read straight through its own figures — the ultra-thin material frosts the scrolled row out while staying translucent enough for the sheet to read as one continuous piece of glass from the traffic lights down to the disk-usage footer. When the window is in the background the sidebar flattens along with the rest of the window's materials, exactly as the system's own sidebars do — that is the system's inactive appearance, not a defect.

### Under the hood

- **The binary's `LC_BUILD_VERSION` was lying about its SDK.** SwiftPM stamps the linked binary with the deployment target for both `minos` and `sdk`, so a build against the macOS 27 SDK declared `sdk 14.0`. AppKit reads that field to choose the window-chrome generation and the control metrics, which is why the app looked a generation behind. `build-app.sh` now restates the SDK the build actually compiled against through the linker's `-platform_version`, producing `minos 14.0 / sdk 27.0` — truthful metadata, with the minimum system version untouched.
- **One place owns the deployment target.** Both bundles' `LSMinimumSystemVersion` and the linker's `-platform_version` now read the same `MACOS_MINOS` variable, instead of two hardcoded `14.0` strings that had to be kept in sync by hand.
- **One component owns the version gate for backdrops.** `LegacyBackdrop` decides whether a backdrop is painted at all: nothing on macOS 26+, where the sidebar's glass has to sample the window's own backdrop to pick up the gradient, and the legacy fill below that, where the window backdrop is the plain window background color and there is no glass to preserve. The check is a runtime OS-version test rather than the binary's SDK declaration, and the legacy branch runs on every launch on macOS 14 and 15 — those systems keep the appearance they had, with the legacy fill applied exactly as before.
- **The footer's frost is a component of its own.** `SidebarFooterBackdrop` picks the footer's material by OS: the ultra-thin material on macOS 26 and later, where the sidebar's glass has to keep sampling the window and an opaque fill would saw a slab off it, and the bar material the footer always wore below that. It runs the same runtime OS-version gate as `LegacyBackdrop`, and the legacy branch runs on every launch on macOS 14 and 15 — those systems keep the footer exactly as it was.
