## Mackit 1.0.8

The window finally wears the system's own macOS 26 clothes — starting with the traffic lights.

- **The traffic lights match the system default again.** The close, minimize and zoom buttons in the top-left corner rendered at the smaller pre-macOS-26 size — 12pt discs with their symbols always visible — while every other current app on the system, System Settings included, drew the macOS 26+ chrome: 14pt discs, 23pt spacing, symbols only while you hover, the softer glass shading. The cause was not the window's design but the build: the app declared itself as built against the macOS 14 SDK, and macOS keys a whole generation of window chrome off that declaration. The window keeps its hidden title bar and full-bleed layout — nothing about the app's own layout changes, only which chrome the system draws on it.
- **System-styled controls take the macOS 26+ metrics with it.** The same declaration also governed control sizing: push buttons, switches, pickers, tables and forms now render at the current sizes — taller, rounder — instead of the pre-macOS-26 ones. This is the appearance the app was already written to pick up on macOS 26 and later; it just never got the chance to.
- **macOS 14 and 15 are unaffected.** The deployment target is unchanged, so the app still installs and runs on macOS 14 and later, and those systems — which have no macOS 26 chrome of their own — keep the appearance they always had.

### Under the hood

- **The binary's `LC_BUILD_VERSION` was lying about its SDK.** SwiftPM stamps the linked binary with the deployment target for both `minos` and `sdk`, so a build against the macOS 27 SDK declared `sdk 14.0`. AppKit reads that field to choose the window-chrome generation and the control metrics, which is why the app looked a generation behind. `build-app.sh` now restates the SDK the build actually compiled against through the linker's `-platform_version`, producing `minos 14.0 / sdk 27.0` — truthful metadata, with the minimum system version untouched.
- **One place owns the deployment target.** Both bundles' `LSMinimumSystemVersion` and the linker's `-platform_version` now read the same `MACOS_MINOS` variable, instead of two hardcoded `14.0` strings that had to be kept in sync by hand.
