## Mackit 1.0.10

App uninstall gets its own tool, and a new large-file analysis answers "what is eating my space" file by file.

- **App uninstall is its own tool.** Every app in `/Applications` and `~/Applications` with its icon, version, size, leftover-file count and last-opened time. A tri-state checkbox per app — bundle and all leftovers, or nothing — expandable per leftover file with its own checkbox, risk label and path. The sheet names running apps before the clean refuses them and offers one-tap "Select all" for unchecked leftovers; the clean runs the same engine as everything else. Apps leave the cleanup scan, which now covers only their regenerable junk ("Scan App Junk").
- **Large file analysis: the disk, file by file.** Walks the whole startup disk and lists every file at or above 500 MB / 1 GB / 5 GB, with icon, name, folder, date and size. It waits for your button, then streams hits in under a strip showing the count, the directories visited, the folder being read and a cancel. Sort by size, name or date either way, search by name, and trash the checked files through the same confirmation flow — with the plain warning that a large file may be a VM image, a database or your project. Unreadable folders are named, a stopped walk labels its list partial, and Documents / Desktop / Downloads are skipped unless you opt in.
- **"Show in Finder" selects the file.** Where Mackit is not permitted to automate Finder, the reveal falls back to opening the folder — the click never reads as a no-op.
- **Fixed:** the uninstall probe could be talked into listing `~/Library` or your documents (probe keys are now plain file names only, and residue paths must resolve inside your home directory); the quit button no longer signals a recycled pid; Stop now stops the scan; a Homebrew action can no longer hang behind its timeout; the protected-path check runs at the moment of the delete; the uninstall icon cache is capped; a symlinked project root is scanned; duplicate project roots no longer show twice; the general cleanup page no longer crashes on a renamed rule id.

### Under the hood

- The walk reuses the disk analysis's traversal — a fixed worker pool over one shared queue, threshold applied while enumerating, so a whole-disk walk retains only the hits. Hits stream the moment they are found: unlike the analysis tree, a hit is a finished fact.
- The threshold and sort menus are one `MenuPill` component riding the shared `GlassSurface`.
- 602 tests across 57 suites (+25 from this feature) cover the scanner's safety rules, the threshold and sort contracts, the streaming order and the page navigation.
